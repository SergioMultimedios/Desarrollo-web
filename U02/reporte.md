En esta unidad se le agregó al proyecto su primer recurso HTTP. La app de la unidad pasada ya arrancaba, pero no respondía nada propio. Se partió de la carpeta U02/inicio, que es la solución de U01. Fueron tres cambios. Al pom.xml se le subió la versión a 0.0.2-SNAPSHOT y se le cambió el nombre y la descripción a la unidad 02, sin agregar dependencias. Se creó la clase SaludoController en el paquete mx.edu.backendacademico.controller. Y se creó el archivo requests.http con las peticiones, para poder repetirlas.

El controlador lleva @RestController y @RequestMapping("/api/v1"). El método saludar() va con @GetMapping("/saludo"), así que la ruta completa se arma entre las dos anotaciones. El método no devuelve texto ni JSON escrito a mano. Devuelve un Map.of("mensaje", "Hola backend") y Jackson lo convierte a JSON cuando sale la respuesta.

Se corrió .\mvnw.cmd clean test y pasó: Tests run: 1, Failures: 0, Errors: 0 y BUILD SUCCESS. En la salida ya se ve que compila 2 fuentes en lugar de 1. Luego se levantó el servidor con .\mvnw.cmd spring-boot:run y se probaron los tres casos de la unidad. El GET a /api/v1/saludo dio 200, con Content-Type application/json y el cuerpo {"mensaje":"Hola backend"}. Con solo cambiarle la ruta, el GET a /api/v1/no-existe dio 404. Y un POST a /api/v1/saludo, que sí existe pero nada más acepta GET, dio 405 Method Not Allowed. Los dos errores también llegan en JSON, con el status, el error y el path.

Al final se detuvo el servidor con Ctrl+C y se repitió la petición del saludo. Ahí ya no hay status de nada. Lo que falla es la conexión, porque no queda nadie escuchando en el 8080. Es distinto del 404 y del 405, porque en esos dos el servidor sí estaba y fue él el que contestó que no encontró la ruta o que no acepta ese método.

Para el reto se le agregó un nombre opcional al saludo, sin que dejara de funcionar cuando no se manda nada. Al método saludar() se le puso el parámetro @RequestParam(defaultValue = "Mundo") String nombre, con su import, y el mensaje se arma en Java con String mensaje = "Hola " + nombre. En requests.http se dejaron las dos peticiones, una sin el parámetro y otra con ?nombre=Ada. Las dos dan 200. La que va sin parámetro devuelve {"mensaje":"Hola Mundo"}, porque ahí entra el defaultValue, y la que lleva ?nombre=Ada devuelve {"mensaje":"Hola Ada"}.

Lo del parámetro y lo de la serialización pasan en momentos distintos. El parámetro se resuelve antes de que corra el método. Spring MVC recibe la petición, le saca el query string, ve que el método espera un @RequestParam llamado nombre y, si no viene en la URL, mete el defaultValue. Para cuando entra a saludar() la variable ya trae valor y nunca llega como null, así que no hay que validarla ahí dentro. La serialización va al final. El método devuelve un Map de Java y Jackson lo convierte a {"mensaje":"..."} ya cuando se está escribiendo la respuesta. Por eso en el código no hay ninguna llave ni comilla de JSON escrita a mano.
